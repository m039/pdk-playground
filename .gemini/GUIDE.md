## 📌 ЗОЛОТЫЕ ПРАВИЛА РАЗРАБОТКИ (CORE MANDATORY RULES)

### 1. Работать только в ветке `develop`
* Основная рабочая ветка для всей разработки — **`develop`**.
* Прямой пуш и прямые коммиты в ветку `main` **СТРОГО ЗАПРЕЩЕНЫ**.
* Все новые фичи, исправления и задачи начинаются от ветки `develop` (например, `feature/...` или `fix/...`) либо коммитятся в рамках рабочего потока `develop`.

### 2. При каждом выполнении задач ОБЯЗАТЕЛЬНО делать Pull Request
* По завершении ЛЮБОЙ задачи, этапа разработки или фичи разработчик / AI обязан:
  1. Зафиксировать изменения в отдельной ветке задачи (ответвлённой от `develop`).
  2. Создать **Pull Request (PR)** с базовой веткой **`develop`** (`base: develop <- head: <branch>`).
  3. В описании PR чётко указать:
     - Список выполненных задач и изменений;
     - Затронутые модули и файлы примеров;
     - Результаты тестов / сборки и метрики использования памяти (ROM/RAM).
* Никаких задач без оформленного Pull Request.

### 3. Автоматический анализ изменений гайда (Self-Inspection)
* **ЕСЛИ ГАЙД (`GUIDE.md`) ИЗМЕНЕН ВЛАДЕЛЬЦЕМ ПРОЕКТА (@m039):**
  - Разработчик / AI-ассистент обязан **НЕМЕДЛЕННО И В ПЕРВУЮ ОЧЕРЕДЬ** проанализировать измененный `GUIDE.md`.
  - Актуализировать внутренний контекст и правила выполнения задач согласно правкам владельца.
  - Сообщить о принятии новых правил и следовать им во всех последующих шагах.

## 🛠 АРХИТЕКТУРА И СТРУКТУРА ПРОЕКТА `pdk-playground`

Проект представляет собой коллекцию примеров прошивок (firmware) и аппаратных схем для микроконтроллеров Padauk (PMS150C, PFS154 и др.) на базе компилятора SDCC и тулчейна [pdk-platformio](https://github.com/m039/pdk-platformio):

| Директория | Описание |
| :--- | :--- |
| `Code/1 Blink/` | Базовый пример мигания светодиодом на GPIO PA4 с циклом задержки (SDCC C) |
| `Code/2 BlinkAsm/` | Мигание светодиодом на чистом ассемблере Padauk (pdk14) с регистрами портов |
| `Code/3 Led PWM/` | Аппаратный ШИМ для плавного затухания светодиода с использованием Timer2 на PA3 |
| `Code/4 Musical Melody (Period Mode)/` | Воспроизведение 8-битных мелодий на пьезодинамике через Timer2 в режиме периода + Python скрипты конвертации MIDI |
| `Code/5 Musical Melody (PWM Mode)/` | Управление громкостью пьезодинамика через регулировку скважности ШИМ + АЦП на PB3 + UART отладка |
| `Code/6 PMS150C-I2C-1Bit ADC/` | Измеритель напряжения VDD и PA4 (1-bit ADC на встроенном компараторе) + программный слейв I2C (адрес `0x2A`) для опроса мастером (Arduino Nano) |
| `PCB/` | Принципиальные схемы платы разработчика (`SCH_PDK Devboard`) и автономного аудиоплеера, проект EasyEDA (`Padauk.eprj`) |

---

## 🎯 СПЕЦИФИКА ОГРАНИЧЕНИЙ PADAUK PMS150C

* **Flash/OTP**: 1 KW (1024 13-битных инструкций / слов). Лимит очень жесткий.
* **RAM**: 64 байта данных (SRAM).
* **Стек**: 8 аппаратных уровней. Избегать глубоких цепочек вызовов и рекурсии.
* **Оптимизация**: Использовать макросы вместо мелких статических функций, минимизировать 16-битные вычисления и дублирование циклов.
